# 制品库（分片上传 + 区间友好发布 + 成品找回分片）

一个用 Flask + SQLite + 本地卷实现的安装镜像制品库：把大镜像切成至多 12 个编号分片分别上传，
发布时按成品顺序提交清单，服务端校验摘要、在两项额度内选择正文布局，成功后通过稳定的文件地址
原样提供支持 `Range` 的下载。构建机丢失分片原件时，值班员可直接在首页从当前成品按发布清单
找回指定分片，校验 SHA-256 后整批补回已收列表。

## 快速开始

### docker compose

```bash
docker compose up --build -d
# 打开 http://localhost:8000/
```

数据存在命名卷 `artifact-data`（正文在 `/data/bodies`，状态在 `/data/repo.db`）。
镜像内默认用 Waitress 提供 HTTP 服务。
`ARTIFACT_SIMULATE_WRITE_FAILURE=1` 可让每次发布在建好新正文、提交可见性事务之前失败，
用于演练回滚。

### 本机

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m artifact_repo --data-dir ./data --port 8000
```

可选参数：`--host`、`--port`、`--data-dir`、`--simulate-write-failure`、
`--server auto|waitress|flask`（默认装了 waitress 就用它，否则退回 Flask 开发服务器）。

线程模型：单进程、多线程。发布在进程内串行化；发布的钉住/解钉也由本进程负责。

## 概念

* **分片**：编号 1–12 的上传单元。同一个号可以覆盖上传；旧正文不会被就地改写。分片可以只占用
  某份正文的一个子区间（从成品找回并选择复用正文时即是如此），同一份正文可被多个相邻分片引用。
* **正文（body）**：`data/bodies/<uuid>.bin` 中不可变的字节文件。上传的分片各有一份正文；
  发布时也允许把相邻的若干整片合并成一份新正文；找回的分片可指向发布正文的子区间，或另存为新正文。
* **发布（release）**：一次成功的成品。清单给出成品顺序下每个分片的号和 SHA-256。
  成品是清单中分片按顺序拼接的结果，发布记录保存切段布局（每段引用一份正文及正文内偏移）。
* **生效发布**：`meta.active_release_id` 指向的发布。`/artifact/<文件名>` 在每个请求开始时
  取当前生效发布并钉住它，直到响应结束。

## 发布流程

1. 读取清单（每行 `分片号 SHA-256`），要求对应分片已上传且摘要一致；顺序即成品顺序。
2. 读取常用区间（每行 `起始偏移 长度 最多打开正文文件数`）与新写正文总字节上限。
3. 规划布局：把清单切成连续的块（“相邻”指**清单/成品顺序上相邻**，与分片号是否连续无关）。
   单块（1 片）复用该分片的现有正文，**不写新字节**；
   多块（相邻 ≥2 片）合并成一份新正文，字节数计入新写额度，但区间内只算 **1 个打开文件**。
   穷举至多 2¹¹ 种切法，要求每个常用区间触及的正文文件数不超过该区间的额度、且新写总量不超上限；
   在可行解中选新写字节最少、文件数最少的方案。无解即拒绝发布。
4. 逐片重算 SHA-256 并同时拼出清单顺序的摘要；写出需要合并的正文；再按实际布局完整读一遍成品，
   与清单拼接摘要比对，并核对总长度。
5. 以上全部通过后才在一个短事务里插入发布、切换 `active_release_id`、把旧发布标记退役。
   任何一步失败（摘要不符、无解、模拟/真实写盘失败）都会清理临时文件，旧成品与已收分片原样保留。

## 从成品找回分片（构建机丢失原件时）

首页“从当前成品找回分片”面板按当前生效发布的清单列出每个可找回分片：成品偏移、长度、所在正文
文件、正文内偏移和 SHA-256。勾选分片并为每个分片选择方式：

* **复用正文（reuse）**：不写新字节，已收分片只保存指向发布正文某个子区间的指针。多个相邻分片
  共用同一份正文文件时只打开一次；同一份正文的“依赖大小”按**整份文件大小只算一次**。
* **另存（copy）**：把该分片对应的子区间复制成一份独立正文，复制的字节计入本次新写额度，此后
  不再依赖原发布正文。

确认前填写两项上限：

1. **本次新写字节上限**：限制这次找回新写出的字节数（即所有“另存”分片长度之和）；
2. **依赖文件总大小上限**：限制找回分片所依赖的正文文件总大小，共用正文按整份大小算一次，
   只有“复用正文”的分片产生依赖。

服务端在写任何字节前独立重算两项额度，**两项都能满足**才继续：先逐片重算 SHA-256 与发布清单
核对（复用核对共享正文的子区间、另存核对新写出的独立正文），再在一个短事务里把分片整批插入
已收列表。成功后页面显示实际新写字节与实际依赖大小。以下任一情况都会**整批不补、原有分片照常
可用**：所选分片号已被占用、确认时成品已换版（页面基于的发布号与当前生效发布不一致）、SHA-256
校验失败或写盘失败。

找回的分片是普通已收分片：即使原发布退役并被回收、进程重启，仍可单独下载（只流式读取该分片
对应的子区间，不会带出同正文里相邻分片的字节），也可以换个顺序或混入新分片再次发布；再次发布
仍然检查所填的打开文件数与新写字节两项额度。

## 下载与回收

* `GET /artifact/current`：稳定地址，始终指向当前生效发布。
* `GET /artifact/<文件名>`：同一内容；文件名即发布时填写的名字。
* 支持单区间 `Range`（含 `bytes=a-`、`bytes=-n`），返回 `206`、`Content-Range`、`Accept-Ranges`、
  与成品摘要一致的 `ETag`；越界返回 `416` 和 `Content-Range: bytes */<size>`；多区间语法按规范忽略、返回整份。
* 下载开始时把发布钉住（`pinned_readers`）。新发布切换后，旧发布进入退役状态，但其正文引用保留到
  在途读者把响应读完（生成器结束才解钉），随后 GC 才能删除无引用正文。
* 每次上传覆盖、发布成功、解钉、手动“回收”都会运行 GC：先释放已退役且无读者的发布的正文引用，
  再删除既不被已收分片引用、也不被任何发布引用的正文文件；进程启动时还会清理无记录的孤儿正文。

## 网页功能

* 上传/替换 1–12 号分片，列出已收分片（大小、正文内偏移、来源、SHA-256）并可删除/单独下载；
  已收分片在发布后保留，下一轮只需覆盖变化的号即可（这也让“发布成功后分片号可供下一轮重用”成立）。
  来源标注区分上传、找回·复用正文与找回·另存；共享正文只下载该分片自己的子区间。
* **从当前成品找回分片**：按发布清单勾选要找回的分片并逐片选择复用/另存，填两项上限（新写字节、
  依赖文件总大小），页面实时预估用量；提交后整批核对 SHA-256 并补入，失败则整批不补。
* 发布表单：成品文件名、清单（预填已收分片的摘要）、常用区间、新写上限、模拟写盘失败勾选框。
* 发布记录（生效/退役、在途读者数）与最近发布/找回尝试（成功/失败原因）。
* **试取实际 HTTP Range**：默认给出一段跨越切段边界的区间；服务端在 `127.0.0.1` 上临时起一个
  同应用监听，用真实 TCP 发出 `Range` 请求，统计实际打开的正文字文件数、本发布新写正文字节数，
  并同时与本地快照比对摘要，显示 HTTP 状态、`Content-Range` 和是否一致。
* `GET /api/state`、`GET /api/range-check?start=&length=` 提供同样信息的 JSON。

## 测试

```bash
.venv/bin/python -m unittest discover -s tests -v
```

包含：布局穷举与两项额度边界、摘要不符/无解/模拟写盘失败时旧成品与分片保留、覆盖上传后分片号
重用、重启后仍取最后成功发布、跨片 `Range` 字节比对、416/HEAD、回环 HTTP 试取统计，以及一条
“下载进行中发布新版本——旧读者读完旧成品、旧正文不提前回收”的并发测试。
`tests/test_recovery.py` 覆盖找回：合并正文的子区间定位、复用零新写/另存独立正文、共享正文
依赖只算一次、两项额度不足/号被占用/确认时换版/摘要不符时整批不补、退役回收并重启后仍可单独
下载、换序混入新分片再发布（仍受两项发布额度约束）、以及一次真实回环 Range 对共用正文只打开
一次文件。

端到端找回演练（对运行中的服务发布→删光分片→找回→退役回收→换序再发布→区间核对）：

```bash
.venv/bin/python scripts/recovery_demo.py http://127.0.0.1:8000
```

已知限制：`docker compose` 只起一个应用进程（Waitress + 单进程 SQLite）；多进程/多副本部署需要
把发布串行化（例如外部锁）并把上传请求路由到同一实例。服务本身没有认证，只适合放在可信内网或
反代后面；当前未实现多区间 `Range`（按 RFC 9110 忽略请求头、返回整份）、断点续传清单和上传并发限流。
启动时会把所有发布记录的“在途读者”计数清零，因此进程崩溃不会永久占住旧正文。

对运行中的服务做端到端演练：

```bash
.venv/bin/python scripts/demo.py http://127.0.0.1:8000
# 或在临时目录自起服务、跑完自动清理：
PYTHON=.venv/bin/python bash scripts/smoke.sh
```

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `artifact_repo/geometry.py` | 纯规划：清单/区间校验、切块穷举、两项额度可行性、共享正文按不同正文计数、诊断信息 |
| `artifact_repo/store.py` | SQLite 模型、分片与正文存储（含子区间分片）、发布事务、成品找回事务、钉住与 GC |
| `artifact_repo/serving.py` | `Range` 解析、按布局打开正文并流式输出（共用正文只开一次、按正文内偏移取字节）、打开文件数统计 |
| `artifact_repo/web.py` | Flask 路由、网页、找回表单、回环 HTTP 试取、JSON API |
| `artifact_repo/templates/` | 页面模板（首页含找回面板与用量预估） |
| `tests/` | 单元、Web、真实 HTTP 端到端、找回专项测试 |
| `scripts/demo.py` | 对运行中服务的上传/发布/跨片区间演练脚本 |
| `scripts/recovery_demo.py` | 对运行中服务的找回全流程演练（发布→删片→找回→回收→换序再发布） |
